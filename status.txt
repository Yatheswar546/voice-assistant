# AI Voice Assistant Project - Progress Summary (Up to Conversation Memory)

## Project Overview

We are building a **production-style AI Voice Assistant** using modern Full Stack and GenAI technologies.

This project is not just about creating a chatbot. The goal is to build an AI assistant similar to ChatGPT with features such as:

* User Authentication
* Persistent Chat History
* Conversation Memory
* Voice Input
* Voice Output
* Sidebar Chat Management
* AI Settings
* Long-term Memory
* RAG (Future)
* Scalable Architecture

Throughout the project, we have been following modern software engineering principles such as modular architecture, separation of concerns, reusable components, clean code, scalability, and maintainability.

# Conversation Memory

Initially Gemini received:

contents: message

Meaning: Every request was independent.

Example:

User:
"What is React?"

User:
"Who created it?"

Gemini answered
"I was created by Google."

because it had no previous context.

---

We changed the implementation to:

```text
Load Conversation
↓
Convert Conversation
↓
Send Entire Conversation
```

Now Gemini receives:

```text
contents: geminiConversationHistory
```

instead of only the latest message.

---

Result:

User:
What is React?

Assistant:
...

User:
Who created it?

Gemini correctly answers:
React was created by Jordan Walke at Facebook (Meta).

Conversation memory is now fully functional.

# Context Window Management (Version 1.0)
After implementing memory, we optimised context handling.

Originally:
```text
Load ALL messages
```

Problem:
* Higher API cost
* Slower responses
* Context window limitations

Solution:
Retrieve only the latest 20 messages.

Implementation:
```text
Find Messages
↓
Sort Descending
↓
Limit 20
↓
Reverse
↓
Gemini
```

Why reverse?
MongoDB returns newest first.
Gemini should read conversations from oldest to newest.
So we reverse before sending.

This provides:
* Better performance
* Lower token usage
* Easier scalability

# Architectural Decisions Made
We intentionally chose NOT to use Gemini's built-in chat session API.

Instead:
MongoDB is our source of truth.

Reasons:
* Persistent chat history
* Sidebar support
* Resume conversations
* Full control over data
* Easier future RAG integration
* Scalable architecture

This is the same approach used in many production AI systems.
